## 1. 项目定位

**一句话**：一个单文件、跨平台的网络调试工作台。C 后端实现全部协议与监听服务，浏览器只做操作界面；本机管理页面不对外，被调试服务按网卡/IP/地址族精确开放到局域网。

**典型场景**

1. 设备作为客户端：向本机 FTP/TFTP/HTTP 服务上传日志、拉取固件 —— 工具是**服务端**。
2. 设备作为服务端：工具用 FTP/TFTP/SSH/Telnet/SMB 客户端去连它 —— 工具是**客户端**。
3. 串口 console、telnet/ssh CLI 调试、SMB 共享读写验证。
4. 多网卡主机：指定从某块网卡、某个 IP、某个地址族收发，验证 IPv6-only / 双栈设备的真实行为。

> 第 4 条是 D7 带来的核心价值：**同一台机器上，能分别用 v4 和 v6、分别从不同网卡去验证设备**，而不是"能连上就行"。

---

## 2. 硬约束

1. 浏览器不能建 TCP/UDP、不能读串口 → 全部协议在 C 后端。
2. 浏览器发 HTTP 受同源策略限制 → HTTP 调试必须后端代理；前端不能直连目标。
3. 前端不持有长连接与大文件状态 → 终端流/串口流/文件传输走 WebSocket 流式。
4. 管理页只绑回环（`127.0.0.1` + `::1` 两个套接字，**不能**用 `::` 双栈通配，否则等于开放到局域网）。

## 3. 总体架构

```
┌────────────────────────── 浏览器（仅本机） ──────────────────────────┐
│ 服务面板(监听) │ 会话工作区 │ 终端 │ HEX │ 文件双栏 │ 监听表/诊断     │
└──────────────────────────────┬────────────────────────────────────────┘
                    HTTP(REST) │ WebSocket
┌──────────────────────────────▼────────────────────────────────────────┐
│ L5 API        HTTP/1.1 + REST + WS + 内嵌静态资源（回环，token）       │
├────────────────────────────────────────────────────────────────────────┤
│ L4 运行层      Service(监听器) ──accept──> Connection                  │
│               Session(客户端) ──connect─> Connection                  │
│               连接 = 协议编解码 + 环形缓冲 + 事件 + 日志                │
├────────────────────────────────────────────────────────────────────────┤
│ L3 协议       ftp(c/s) │ tftp(c/s) │ http(c) │ telnet(c) │ ssh(c)     │
│               smb(c, v2/3) │ raw tcp/udp(c/s) │ serial                 │
├────────────────────────────────────────────────────────────────────────┤
│ L2 传输       socket 抽象 + 监听规划器 + TLS + 串口 I/O                │
├────────────────────────────────────────────────────────────────────────┤
│ L1 平台       网卡枚举 / socket / 串口 / 文件 / 编码 / 错误码 / 时钟   │
│               Win32 与 POSIX 两套实现，接口一致                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 对象模型（关键区分）

- **Service（服务）**：长期存在的监听器，如「FTP 服务，绑 eth1 的 v4+v6，端口 2121」。有启停、连接数、允许名单、根目录。生命周期长，配置持久化。
- **Session（会话）**：一次主动连接，如「SSH 到 192.168.1.10:22，从 eth1 发出」。随用随建。
- **Connection（连接）**：Service 被连上后产生的每一条链路，或一个 Session 的底层链路；一个连接一个线程。

UI 上分成「服务」和「会话」两个空间，避免把监听器和主动连接混在一起。

### 3.2 并发模型

- 每连接一线程 + 阻塞 socket + 环形缓冲（无锁单读单写）。
- 监听器只做 accept，业务交给连接线程。
- WS 推送走每连接一个发送队列，有上限；超限则暂停读或丢帧并告警（背压）。
- 理由同 v0.1：并发量小，线程模型直白，协议状态机不易写错。

### 3.3 技术选型

| 用途 | 选择 | 许可 | 备注 |
|---|---|---|---|
| HTTP + WS 服务 | civetweb | MIT | 可嵌入、自带 WS，双平台 |
| TLS | OpenSSL 3（首选）/ mbedTLS | Apache-2.0 | OpenSSL 兼容性优先 |
| SSH 客户端 | libssh2 | BSD-3 | 自己建 socket 后交给它，可控 IPv6/源绑定 |
| SMB 客户端 | libsmb2 | LGPL-2.1 | SMB2/3；**IPv6 能力待 M0 验证** |
| HTTP/FTP/TFTP/Telnet | 手写 | — | 调试器需要原始报文可控；FTP 需 EPRT/EPSV 细节 |
| JSON | cJSON | MIT | |
| 构建 | CMake + vcpkg（manifest） | — | MSVC 2022 / GCC 11+ / Clang |
| CI | GitHub Actions 或本地脚本 | — | Windows + Ubuntu 双矩阵编译 + 单测 |
| 前端 | 原生 ES Module + xterm.js | MIT | 零框架，构建期内嵌进 exe |

## 4. 多网卡绑定与地址族策略 ⚠（本轮新增，重点）

### 4.1 三个维度组合

每个服务（以及每个客户端会话）都要能配置：

| 维度 | 取值 |
|---|---|
| 协议族 family | `v4` / `v6` / `dual` |
| 绑定范围 bind | `any`（所有地址）/ `iface`（某块网卡的全部地址）/ `addr`（某个具体地址） |
| 端口 port | 固定端口（允许 0 = 自动分配） |

对客户端会话额外有：**源地址绑定**（不改 IP 时也常需要"从哪块网卡出去"）。

### 4.2 套接字规划（监听规划器）

绑定范围与协议族**不是正交的**：绑到具体地址时，"双栈"没有意义。规则如下：

| 绑定范围 | 协议族 | 套接字规划 |
|---|---|---|
| any | v4 | 1 × `0.0.0.0:port` |
| any | v6 | 1 × `[::]:port`，`IPV6_V6ONLY=1` |
| any | dual | 1 × `[::]:port`，`IPV6_V6ONLY=0`（v4 以映射地址进入）；若平台策略不允许，退化为 v4 + v6 两个套接字 |
| iface(i) | v4 | 该网卡**每个** v4 地址一个套接字 |
| iface(i) | v6 | 该网卡**每个** v6 地址一个套接字（带 scope id） |
| iface(i) | dual | v4 地址 + v6 地址各一个（**无法单套接字**） |
| addr(a) | 由 a 决定 | 1 个；UI 上 dual 选项置灰 |
| 回环（管理页） | — | 固定 2 个：`127.0.0.1` + `::1` |

补充规则：

- 不用 `SO_BINDTODEVICE` 绑网卡：Linux 上需要 `CAP_NET_RAW`，Windows 没有对应能力。**按地址逐个绑**更通用、权限要求最低。
- 网卡多地址时逐个绑定，任一地址失败（如 IPv6 临时地址消失）只告警、不整体失败。
- 地址会变（DHCP、热插拔）：监听管理器需在地址变化时**重建套接字**（Windows `NotifyIpInterfaceChange`，Linux netlink `RTM_NEWADDR/DELADDR`；先做 10s 轮询兜底）。
- 冲突检测：同一 `(family, addr, port)` 重复、通配与具体地址重叠、端口已被占用，都要在启动前给出**具体是哪条冲突**，而不是笼统的"bind failed"。

### 4.3 由绑定引出的协议细节（容易踩坑的地方）

**FTP（影响最大）**

- 控制连接可能从双栈套接字进来，对端可能是 `::ffff:192.168.1.5` → 必须归一化判断真实家族。
- PASV 的 `227 (h1,h2,h3,h4,p1,p2)` 必须回**控制连接本端的实际地址**，不能回 `0.0.0.0`；多网卡下回错地址是最常见的"被动模式连不上"。
- IPv6 必须实现 **EPSV/EPRT**；`PASV` 在纯 v6 下应回 `522` 并提示用 EPSV。
- 数据套接字必须绑**与控制连接相同的本地地址与家族**，端口从配置的被动端口段取；取不到回 `425`。
- NAT / 端口映射场景需要「对外通告地址」覆盖项，独立于绑定地址。
- 服务端主动模式（PORT/EPRT）默认只允许连回**控制连接的对端 IP**，防 FTP bounce 被当跳板。

**TFTP**

- 服务端监听 69，但每个请求要用**新端口**回包（TID 规则），且源地址必须是**请求到达的那个本地地址**。
- 因此：绑具体地址时天然正确；绑 `any` 时必须取包信息（Linux `IP_PKTINFO`/`IPV6_RECVPKTINFO`，Windows `WSARecvMsg`），否则多网卡下会从错误网卡回包。
- IPv6 链路本地地址必须带 scope id；客户端也要校验回包来自正确的 TID 与地址。

**HTTP 客户端**

- IPv6 字面量 URL：`http://[2001:db8::1]:8080/path`，Host 头要带方括号；URI 解析器必须支持。
- 源地址绑定在 `connect()` 前 `bind()` 即可；TLS 的 SNI 仍用主机名，不用 IP。

**SMB / SSH**

- SSH：libssh2 接受现成 socket，IPv6 与源绑定都可控。
- SMB：libsmb2 自管连接，**能否指定源地址/是否支持 IPv6 字面量待验证**；若不支持，UI 明确标注"SMB 会话仅 IPv4"。

**Telnet / 裸 TCP/UDP**

- 纯 socket 层，天然支持；UDP 需要 `sendto` 时选对本地地址（同 TFTP 的 pktinfo 问题）。

### 4.4 客户端出站策略

- 协议族：`自动` / `仅 IPv4` / `仅 IPv6`。`自动` = `getaddrinfo` 顺序 + 逐个尝试，连接日志记录**最终实际使用的地址**（调试工具必须让用户看到这一点）。
- 双栈目标超时策略：首个地址失败/超时（可配，默认 1.5s）后切下一个；不实现严格 Happy Eyeballs 竞速（首版）。
- 源地址绑定：可选“任意 / 指定网卡 / 指定地址”；绑定失败要给出明确原因（地址不存在、权限、已被占用）。
- 显示解析结果：连接前把 A/AAAA 记录列出来，便于判断"到底是解析错了还是网络不通"。

### 4.5 已知平台差异（必须显式处理）

| 项 | Windows | Linux |
|---|---|---|
| 地址复用 | `SO_EXCLUSIVEADDRUSE`（防端口劫持） | `SO_REUSEADDR`（快速重启） |
| `IPV6_V6ONLY` 默认 | 0（双栈） | 0，但受 `bindv6only` sysctl 影响；**统一显式设置** |
| 网卡枚举 | `GetAdaptersAddresses`（含友好名、GUID、ifIndex） | `getifaddrs` + `/sys/class/net`（operstate、MTU） |
| 链路本地地址 | scope = ifIndex | scope = ifname，常写作 `%eth0` |
| 低端口 (<1024) | 无限制 | 需 root 或 `CAP_NET_BIND_SERVICE` |
| 防火墙 | 首次监听弹窗 | nftables/iptables 可能静默丢弃 |
| 映射地址 | 双栈下 v4 显示为 `::ffff:a.b.c.d` | 同 |

### 4.6 UI 呈现

- 新建服务表单：`协议 → 网卡下拉（显示每块网卡的地址列表、up/down）→ 地址族（v4/v6/双栈，按所选范围自动置灰）→ 端口 → 根目录/认证等`。
- 「测试绑定」按钮：不真正启动服务，只做 bind 试探，直接报冲突。
- 服务卡片上直接展示：**实际监听地址列表**（一行一个 `family addr:port`）+ 可达性提示。
- 全局「局域网暴露」徽标：只要有非回环监听，顶部常驻提示，可一键全部停止。
- 诊断页：监听表、防火墙状态提示、从本机某地址自连测试。

## 5. 功能需求

### 5.0 通用

| 分类 | 需求 |
|---|---|
| 会话 | 新建/命名/分组/克隆/保存/导入导出(JSON)/多标签 |
| 连接 | 超时、重试、断线自动重连、取消、连接日志（含实际地址与耗时） |
| 视图 | 文本 / HEX（偏移+ASCII）/ 原始报文 / 时间戳 / 收发分色 / 暂停滚动 / 搜索 / 导出 |
| 发送 | 文本/HEX/文件；行尾；编码 UTF-8/GBK/ASCII；定时发送；快捷指令；循环测试 |
| 日志 | 按会话/服务落盘、滚动、导出 |
| 状态 | 连接状态、字节/速率、错误码 + 可读原因 |
| 安全 | 密码 DPAPI（Win）/ 本地密钥（Linux）加密；日志脱敏 |
| 全局 | 中英文、深浅主题、快捷键、单实例、托盘 |

### 5.1 串口

- 必做：枚举（Win 含 VID/PID 友好名；Linux 列 `/dev/ttyUSB*`、`/dev/ttyACM*` 与 `/dev/serial/by-id`）、5–8 数据位、校验、停止位、流控、任意波特率、DTR/RTS、文本+HEX、定时发送、日志。
- 应做：多串口并发、自动重连、文件发送、编码切换、≥921600 不丢数据。
- 平台：Linux 需提示 `dialout` 组权限；打开失败要给出"权限不足/被占用"的区分。
- 后做：RS-485 方向控制、数据统计。

### 5.2 Telnet ⚠

- 必做（客户端）：IAC 协商（ECHO/SGA/NAWS/TTYPE/BINARY）、终端类型/窗口、VT100 渲染、CR/LF 规范化、编码、重连、**原始字节模式**（纯 TCP 透传）。
- 服务端（D8 已定，排在 M3 后）：接受连接、IAC 协商、回显策略；可选脚本化应答（按行匹配正则回复），适合"设备主动上报"类调试。
- 后做：LINEMODE、脚本化 CLI。

### 5.3 SSH（仅客户端）

- 必做：密码 / 公钥（RSA/ECDSA/Ed25519 + passphrase）/ keyboard-interactive；known_hosts 三态；shell + PTY + resize；exec；保活；编码。
- 应做：SFTP（与 SMB/FTP 共用文件面板）；**算法兼容模式**（ssh-rsa、dh-group1-sha1、aes-cbc）—— 老设备联调刚需。
- 后做：端口转发、ProxyJump。
- 验证：OpenSSH 9.x 与老设备各一台；断网 30s 内可重连。

### 5.4 HTTP ⚠

- 必做（客户端）：方法/URL/查询参数/Header 表/Body（无、form、JSON、文本、文件）；Basic/Bearer；超时；重定向开关；代理；TLS 校验开关 + 自签证书；原始请求预览/编辑；响应状态/头/体；耗时（TTFB/总）；格式化/HEX/预览；gzip；chunked；Cookie；历史；环境变量；集合。
- 应做：multipart 上传、响应存文件、断言、cURL 导入。
- 后做：HTTP/2、WebSocket 客户端；**服务端 Mock 已确认后置（D10）**，不进首版。
- 不做：页面渲染/JS 执行。

### 5.5 FTP（客户端 + 服务端）

**客户端**

- 登录（匿名/账号）、主动 PORT/EPRT、被动 PASV/EPSV、LIST/NLST/MLSD、上传/下载/续传(REST)/删除/重命名/建目录、ASCII/BINARY、进度/速率/剩余时间、取消、目录树、拖拽、GBK/UTF-8 编码、NOOP 保活。
- 应做：FTPS（AUTH TLS 显式/隐式）、递归传输、FEAT 协商、**原始命令控制台**。

**服务端**

- 账号（匿名/多用户）、根目录隔离、只读/读写、被动端口段、**对外通告地址**、同时连接数上限、每连接限速（后做）。
- 必须实现 EPSV/EPRT（IPv6 刚需）；PASV 地址按控制连接本地地址生成。
- 安全：根目录越界与符号链接逃逸必须拦住；主动模式默认只连回对端 IP。

**不做**：SFTP（归 SSH）、SCP。

### 5.6 TFTP（客户端 + 服务端）

- 必做：RRQ/WRQ、DATA/ACK/ERROR/OACK、重传与超时、`blksize`/`tsize`/`timeout`（RFC 2347–2349）、TID 正确性、进度。
- 服务端：指定根目录、只读/读写、并发多客户端、逐块日志、源地址正确（见 4.3）。
- 应做：`windowsize`（RFC 7440）、允许多个服务实例（不同网卡/端口）。
- 安全：根目录越界、写入大小上限、允许名单。
- 后做：组播 TFTP。
- 验证：与 busybox tftp 互通；100MB 固件 MD5 一致；5% 丢包可完成。

### 5.7 SMB（客户端，SMB2/3）

- 必做：SMB2/2.1/3.0–3.1.1 协商、NTLMv2 认证、共享枚举、浏览、上传/下载/删除/重命名/建目录、大文件流式、进度、签名。
- 后做：SMB3 加密、DFS。
- 不做：SMB1、**SMB 服务端**（成本极高，不建议）。
- 风险：libsmb2 的 IPv6/源绑定能力待验证；LGPL 链接方式需定（DLL 动态链接最稳）。

### 5.8 基础协议（首版必做）

原始 TCP 客户端/服务端、UDP 客户端/服务端 + HEX 收发。这是所有协议的底座，也是排障最常用。

### 5.9 明确不做（首版）

抓包(PCAP)/深度解析、脚本引擎、多用户权限体系、移动端、SMB 服务端、SSH 服务端。

## 6. 非功能需求

| 维度 | 要求 |
|---|---|
| 平台 | Windows 10 1809+ x64、Ubuntu 20.04+ / Debian 11+ x64 首发；macOS 不承诺但保持 POSIX 可移植 |
| 交付 | 单文件绿色版：Windows 单 exe；Linux 单二进制（依赖尽量静态）。启动自动开浏览器 |
| 管理面 | 仅回环；随机 token；校验 Host/Origin 防 DNS rebinding；无 CORS 通配 |
| 服务面 | 按配置绑网卡/IP/地址族；可选 CIDR 允许名单；暴露时全局提示 |
| 权限 | Linux 低端口需 root/capability → 默认建议高位端口（2121/6969/2323），可切标准端口并提示所需权限 |
| 性能 | 串口 921600 不丢；单会话 100Mbps；≥10 并发连接；前端 1 万行/秒不卡 |
| 资源 | 空闲 < 40MB；1GB 传输峰值 < 150MB（流式） |
| 可靠性 | 异常输入不崩溃；单连接异常不影响进程；监听失败可定位到地址/端口/原因 |
| 兼容 | GBK/UTF-8；非标准实现容忍；老算法开关 |
| 合规 | 第三方许可清单；避免 GPL 静态链接；LGPL 组件动态链接 |
| 可维护 | 分层、每协议独立目录、编解码单测、统一错误码 |

**Linux 低端口说明（重要）**：21/23/69 均 <1024。普通用户运行会 `EACCES`。三种方案：① 默认用高位端口；② 用户 `setcap cap_net_bind_service=+ep`；③ root 运行（不推荐）。产品上默认 ①，UI 明确提示。

## 7. 界面草案

- 左侧：**服务**（监听器列表，带运行状态/连接数）与**会话**（历史连接）两棵树。
- 主区：多标签（终端 / HEX / HTTP 编辑器 / 文件双栏 / 服务配置）。
- 底部：状态栏 + 全局监听概要（`3 个服务在监听，2 个对局域网开放`）。
- 服务配置页：协议 → 网卡 → 地址族 → 端口 → 根目录/认证 → 允许名单 → 「测试绑定」→「启动」。
- 诊断页：监听表、地址冲突、防火墙提示、自连测试。

## 8. 接口草案

```
GET    /api/net/interfaces              -> 网卡 + 地址（family/prefix/scope/up）
POST   /api/net/test-bind               {port, family, bind} -> {ok, conflicts[]}
GET    /api/services                    -> 监听器列表与状态
POST   /api/services                    {protocol, port, family, bind, options}
POST   /api/services/{id}/start | stop
GET    /api/services/{id}/connections   -> 当前连接
DELETE /api/services/{id}
POST   /api/sessions                    {protocol, host, port, family, bind_local, options}
POST   /api/sessions/{id}/connect | disconnect | send
GET    /api/sessions/{id}/resolve       -> A/AAAA 解析结果
WS     /ws/session/{id}                 数据/状态/日志/进度
WS     /ws/events                       全局：服务状态、错误、通知
```

- 错误：`{code, message, detail, sys_errno, addr}` —— `addr` 是绑定失败的关键信息。
- 鉴权：`X-Auth-Token`；WS 同。

## 9. 数据与配置

```
Windows: %APPDATA%\NetDebug\
Linux:   ~/.config/netdebug/
  config.json     全局设置
  services.json   服务定义（网卡用 GUID/ifname + 地址快照，启动时重新解析）
  sessions.json   会话与历史
  logs/  downloads/  keys/  known_hosts
```

网卡引用策略：存**稳定标识**（Windows GUID、Linux ifname）+ 展示名，启动时若不存在则报"网卡缺失"而不是静默绑错。

## 11. 风险

1. **libsmb2 的 IPv6 / 源地址绑定能力未知** → M0 spike；不行就明确降级为 SMB 仅 IPv4。
2. **FTP 多地址场景**：PASV 回错地址、NAT 通告地址、双栈混杂 —— 最容易出"偶发连不上"，需要真实设备回归。
3. **TFTP 源地址**：通配绑定时不取 pktinfo 就会从错误网卡回包，且现象隐蔽。
4. **Linux 低端口权限**与防火墙静默丢包，用户会误判为"工具坏了" → 诊断页必须给出可读原因。
5. **跨平台成本**：socket/串口/路径/编码/错误码五套差异，容易在 M1 之后才暴露 → 平台层必须在 M0 一次做对。
6. **LGPL（libsmb2）静态链接**合规 → 动态链接。
7. **范围膨胀**（HTTP/2、SMB 服务端、HTTP Mock 服务端）→ 用 §5.9 守住。

## 12. 决策状态

**已关闭（v0.3）**

| 问题 | 结论 |
|---|---|
| Telnet 服务端 | 要做（D8），M3 之后 |
| SMB 角色/版本 | 仅客户端、仅 SMB2/3（D9） |
| HTTP 服务端 Mock | 后置（D10），不进首版 |
| 客户端源网卡/源 IP | 要做（D11），纳入 M0 绑定层 |

**P1（按默认值推进，如无异议不再单独确认）**

1. **服务默认绑定策略**：新服务默认 `127.0.0.1`，另有显著「允许局域网访问」开关，记住上次选择。
2. **Linux 低端口**：默认高位端口（2121/6969/2323），可切标准端口并提示 `setcap` 方案。
3. **macOS**：不在首版范围，代码保持可移植。
4. **安装包**：先出绿色版，MSI/deb 后补。
